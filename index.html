1.1 — Tensors & shapes

A tensor is an array of numbers with any number of dimensions. Its shape tells us how many elements exist along each axis.

Scalar5
shape []
Vector[2, 5, 7]
shape [3]
Matrix2 × 3
shape [2,3]
3D tensor32 × 128 × 768
shape [32,128,768]
Intuition

A shape is the address system of your data. In LLM code, understanding shapes is often more important than understanding the actual numbers.

Math

X ∈ R^(B×T×C) means that X has three axes of sizes B, T, and C.

Code
X.shape
X.reshape(...)
X.transpose(...)
LLM connection

[B,T,C] commonly means batch, token position, and embedding/channel dimension.

Common tensor operations 
X.shape = [2, 3]

X * Y          # element-by-element multiplication
X.T            # transpose a 2D matrix
X.reshape(3,2) # same data, new shape
X.mean(axis=0) # average along one axis
Do not confuse * and @.

* multiplies matching elements. @ performs matrix multiplication.

1.3 — Axes & reductions

An axis is one dimension of a tensor. A reduction combines values along an axis and usually removes that dimension.

Before
[32,128,768]
sum(axis=1)
combine the 128 token positions
After
[32,768]
X =
[[1, 2, 3],
 [4, 5, 6]]

X.sum(axis=0)  → [5, 7, 9]
X.sum(axis=1)  → [6, 15]
X.mean(axis=0) → [2.5, 3.5, 4.5]
Best mental model

sum(axis=n) means: “collapse axis n by summing over it.” This remains correct for 2D, 3D, 4D, and beyond.

1.4 — Broadcasting

Broadcasting lets a smaller tensor participate in an elementwise operation with a larger tensor when their shapes are compatible.

X : [32, 128, 768]
b :           [768]

X + b → [32, 128, 768]

Shapes are compared from the right. Dimensions are compatible when they are equal, or when one of them is 1.

Concrete example 
X =
[[1, 2, 3],
 [4, 5, 6]]

b = [10, 20, 30]

X + b =
[[11, 22, 33],
 [14, 25, 36]]
Why it matters

A bias vector such as b[D] can be added to every token in every sequence without manually copying it to [B,T,D].

1.5 — Linear transformations: the workhorse operation

A neural network constantly transforms vectors using a weight matrix and often a bias:

y = xW + b
Intuition

The weights mix and re-express the input features into a new representation.

Math

If x:[C] and W:[C,D], then y:[D].

Code
y = x @ W + b
LLM connection

Attention projections Q/K/V and MLP layers are built from linear transformations.

X.shape = [B, T, C]
W.shape = [C, D]
b.shape = [D]

Y = X @ W + b
Y.shape = [B, T, D]
Key idea

The same matrix W is applied to every token. Training means discovering useful values for W and b.

1.6 — Functions & derivatives

A function maps an input to an output. A derivative tells us how sensitive the output is to a small change in the input.

f(x) = x²     ⇒     f′(x) = 2x
Intuition

The derivative is a local slope: “if x moves a little, how much does f(x) move?”

Math

At x=3, f′(3)=6. A tiny change Δx changes the output by about 6·Δx.

Code
x = 3
slope = 2 * x
LLM connection

Training needs the sensitivity of the loss to every parameter.

Derivative playground: f(x) = x²
x = 2.0 → f(x) = 4.00 → f′(x) = 4.00
d(x²)/dx = 2x
d(x³)/dx = 3x²
d(eˣ)/dx = eˣ
d(log x)/dx = 1/x

1.7 — Partial derivatives & gradients

A neural network does not have one parameter. It has many. When a function depends on several variables, we differentiate with respect to one variable at a time.

L(w₁,w₂) = w₁² + 3w₂
∂L/∂w₁ = 2w₁
∂L/∂w₂ = 3

gradient ∇L = [2w₁, 3]

The gradient is a vector containing all these local sensitivities. For a model with millions or billions of trainable parameters, the idea is identical.

Gradient descent
θ ← θ − η∇L

θ is the collection of model parameters, η is the learning rate, and ∇L tells us how the loss changes.

If gradient is positive

Increasing the parameter increases the loss locally, so gradient descent moves it downward.

If gradient is negative

Increasing the parameter decreases the loss locally, so gradient descent moves it upward.

If gradient ≈ 0

The loss is locally insensitive to that parameter.

LLM training

Repeat forward → loss → gradients → parameter update over many batches.

1.8 — The chain rule: the core of backpropagation

Neural networks are compositions of operations. The chain rule lets us propagate sensitivity backward through that composition.

x = 2

a = 3x       → a = 6
b = a²       → b = 36
L = b + 1    → L = 37

Now work backward:

∂L/∂b = 1
∂b/∂a = 2a = 12
∂a/∂x = 3

∂L/∂x = (∂L/∂b)(∂b/∂a)(∂a/∂x)
       = 1 × 12 × 3
       = 36

This is backpropagation.

Autograd does not use a fundamentally different idea. It records operations during the forward pass and automatically applies local derivative rules in reverse.

1.9 — Probability distributions

A language model does not directly output “the next word.” It assigns a score to every possible next token, then turns those scores into a probability distribution.

France
0.91
Paris
0.04
Europe
0.03
Other
0.02
pᵢ ≥ 0    and    Σ pᵢ = 1
Distribution

A list of possible outcomes and their probabilities.

Conditional probability

An LLM estimates P(next token | previous tokens).

Sampling

Generation can choose a token according to this distribution instead of always selecting the largest value.

Training

The observed next token tells us which probability should have been high.

1.10 — Logits, exp, log & softmax

The raw outputs of the model are called logits. They can be any real numbers. Softmax converts them into probabilities.

softmax(zᵢ) = exp(zᵢ) / Σⱼ exp(zⱼ)
Softmax playground

Change the three logits. Notice that adding the same constant to all logits does not change the probabilities.

softmax([2, 1, 0]) ≈ [0.665, 0.245, 0.090]
Why exp?

Exponentials are always positive and emphasize relative score differences.

Why log later?

Logs turn products into sums and strongly penalize assigning tiny probability to the correct token.

Numerical stability

Implementations usually compute softmax(z − max(z)). Subtracting the same constant does not change softmax but prevents huge exponentials from overflowing.

1.11 — Cross-entropy / negative log-likelihood

If the correct next token has predicted probability p, the basic language-model loss for that token is:

loss = −log(p)
Loss playground
p = 0.800 → loss = 0.223
p=0.99 → loss≈0.010
p=0.80 → loss≈0.223
p=0.10 → loss≈2.303
p=0.01 → loss≈4.605

For a sequence, we average or sum this quantity over token positions:

L = −(1/N) Σₜ log P(xₜ₊₁ | x₁…xₜ)
"The cat sat on the mat"

The       → predict "cat"
The cat   → predict "sat"
cat sat   → predict "on"
sat on    → predict "the"
on the    → predict "mat"
The training objective in one sentence

Adjust the model parameters so that the probability of the token that actually came next becomes larger across the training data.
